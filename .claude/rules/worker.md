# Authority Worker (`worker/`)

ADR 0008 is the contract: one Worker and one SQLite Durable Object, minimal by design.

- No game loop and no simulation ticking on a timer. Handle messages and alarms only. Encounter refereeing (M7) runs timers only while a fight is active.
- Budgets:
  - ≤ 1 request-equivalent (20 incoming WebSocket messages) per player-minute outside fights;
  - ≤ 10 SQLite row writes per player-hour.
  Meter usage per UTC day and queue new sessions before any free-tier limit is reached, never after.
- Handlers are idempotent (keyed by transaction hash) and do every state change in a single SQLite transaction. Schema changes are numbered migrations (`worker/schema.ts`), applied in one transaction at start-up; one that needs the time it runs is a function of `(sql, now)`. Migration 12 adds the players' place out of the water (`left_*`, M12 T10). Migrations 6, 8 and 11 are the world renewals (ADRs 0040, 0055, 0061): `world` holds the epoch (4), reset time, the world's `seed` and `clock` (the one row of `ponds`, made on first use by `worldRow` in `worker/world.ts`, takes them: its id names the world in snapshot signatures and fight logs) and `ip_salt`, `players.epoch_seen` the epoch each identity was told about; migration 8 also empties `encounters` and the away reports, migration 11 also the ponds.
- Use hibernatable WebSockets (`ctx.acceptWebSocket`) and keep per-socket state in attachments. Protocol pings use auto-response so they don't wake the object.
- The hub's indexes (M13 T2, `worker/seats.ts`, `hub.seats`, memory only): each seated player's socket, the line in ticket order, the sockets yet to say hello with their deadlines, live court asks both ways (`courtPairs`), and each seated player's witness candidacy (`avail`, IP hash, saved play and strike). A message finds sessions only through them (`seated(hub, player)` is one attachment read), never by walking `ctx.getWebSockets()`: only a wake (`Authority.rebuildSeats`, the directory's and crowds' rebuilds) and the E2E restart do, through `socketsOf`. Every attachment write goes through `keep(hub, ws, session)` (`socket.ts`), which notes it in the indexes; a socket already closing never takes a seat from the open one holding it. Saved play is read at sign-in (`playOf`) and kept with every record that changes a creature's `active_ms` (`Ledger.played`, taken back if its transaction throws); a strike sets `struckUntil`. So `eligible` reads no SQLite row and no attachment beyond its candidates' (each one's duties of the hour and credit since its last record). `hubReads` counts attachment reads and `getWebSockets()` calls; `worker/hub-scale.test.ts` (heavy) checks that every message type costs the same reads with 20 and with 200 seated. A test that writes a seated player's `creatures` or `players` rows directly calls `seats.reload(player)`, and one that edits an attachment uses `keep` (the kits' `editSession`, `editWitness`).
- Accept requests only from the Pages origin and localhost. Validate every message with the shared codecs. Rate-limit each session.
- Secrets (TURN key, the Cloudflare token for deploys) come only from Worker secrets or GitHub secrets. Never put them in code, logs, responses or tests.
- Tests run offline in workerd (`@cloudflare/vitest-plugin`) and through local `wrangler dev`, with drand and Cloudflare APIs faked or replayed from fixtures.
- `Authority` (`worker/authority.ts`) keeps the object's state, the alarm and the message dispatch; the handlers live by area as functions of `Hub` (`worker/socket.ts`, with `Session` and the send helpers): `sessions.ts` (sign-in, admission, seats, signaling), `spawn.ts` (where a creature enters the water, and the anchors), `lives.ts` (genesis and life), `offspring.ts` (mating and offspring), `engage.ts` (lock-in, and joins into a running fight through `admit` in `fights.ts`; each fighter's worth as prey comes from `worthOf` in `farming.ts`, reads only; the movement check at lock-in (M10 T11, ADR 0059): the target's `lock-state.seen`, each verified as the engage's own snapshot and else ignored, ordered with the attacker's engage snapshot through `jumped` in `movement.ts`, refuses `engage:moved`, releases both and flags `teleport` once per creature, except within `AFTER_FIGHT_MS` (3 s) of the attacker's last fight's end, `Fights.fightEnded`; the sight check (M11 T3, ADR 0062): an in-time answer whose `seen` holds none of those verified snapshots refuses `engage:unseen` and releases both with no flag, while a late answer and a join stay unchecked; hub tests answer through `answer` in `fight-test-kit.ts`, which sends the attacker's snapshot in `seen` unless told otherwise) and `settle.ts` (a fight's end: its records, each fighter's locked time and the signed settlement through `Ledger.settle` in `ledger-encounter.ts`, then `died` and `enc-end` with the document; a settlement that throws writes nothing, flags `settle-failed`, closes the row and sends each connected fighter `enc-end` without a document, then `life` as the ledger holds it). Locks and running fights live in memory in `fights.ts` (`hub.fights`: the `Referee`, the authority's `Encounter` and one timer per lock for the next deadline), on `hub.clock` (`now`, `after`, `cancel`), which hub tests swap for a hand-moved clock (`useFightHub` in `worker/fight-test-kit.ts`) instead of waiting on real milliseconds. Its `hatched()` dates each identity past the young window, so fights there run at worth 1 unless a test says otherwise (`firstSeenAgo`). The ledger dates records on `hub.clock`, and the life clock (`LifeState.t`, its binding and every report's `now`) runs on it too; the hatch bucket, courtship, usage and admission stay on `Date.now()`.
- Fights persist their log (ADR 0053, migration 7): one `encounters` row per fight through `hub.fightStore` (`worker/fight-store.ts`). It is inserted before `enc-start` is sent (a failed insert releases the lock and refuses the attacker `engage:stale`), each join is written before its `enc-join`, the final frames follow every `BATCH_FRAMES` (10, a worker constant) and at once when a participant's socket closes (`drop`), and the settlement's transaction writes the tail, the countersigned document (`settlementOf`) and `open = 0` (`FightStore.seal`, handed to `Ledger.settle` as the `log` of its input). Batch writes leave the indexed `open` column alone, so each costs one row. Its rows count in `ledger.rowsWritten`; hub tests that bound a fight's other writes use `rowsBesideLog` (`fight-test-kit.ts`). Retention (M9 T10, ADR 0056, migration 9): the row's `frames` hold the packed log (`worker/fight-pack.ts`: 4-byte big-endian codes, `0xFFFFFFFF` for the fallback, base64, widths from the start's fighters and the joins; a row written as JSON still reads), which is why the referee refuses code `0xFFFFFFFF`. `FightStore.seal` then prunes (`prune(settlement.t)`): up to `PRUNE_PER_SETTLEMENT` (4) settled rows started `LOG_KEEP_DAYS` (14) or more before, oldest first through the partial index `encounters_kept`, get `start`, `joins`, `frames` and `fighters` blanked (id, pond, `t`, `persisted` and the settlement stay), so `fightProof` answers `log: null` and `FightStore.read` null. A log's prune never touches records, commitments, beacons or settlements (only the witness commitments' own prune, below, deletes commitments). The usage row's `db_bytes` is `ctx.storage.sql.databaseSize` at the day's first flush, and `GET /v1/audit` shows it as `storage: { bytes, limit }`. `npm run report:storage` regenerates `docs/perf/storage.md`.
- Recovery (`worker/recover.ts`, M8 T5): the constructor's `blockConcurrencyWhile` runs `recoverFights` after the migrations, and so does the alarm. Each open row the object doesn't hold is rebuilt (the lock, the encounter replayed from the log, the `Referee` restored at the log's length with its joins); each connected participant gets `enc-start` and the history (`resend` in `fights.ts`), and then `tick` finalizes every frame past its deadline with `null`, settling a fight that ends so. A row whose fighters already hold its records (left open by a close before M8 T8, which now closes it in the settlement's transaction) is only closed. One that no longer rebuilds (or whose recovery throws) is given up as a failed settlement is: `recover-failed` flagged once, the row closed, the locks released, and each connected participant sent `enc-end` without a document, then `life` as the ledger holds it (`backToLedger` in `settle.ts`). A lock still waiting for its answer has no row and leaves nothing.
- Sign-in during a fight (M8 T6): a participant of a running fight keeps its seat while away (`awaySeats` in `sessions.ts` counts it world-wide in `MAX_SESSIONS`, and its sign-in skips the queue). `enter` seats it and sends `welcome`, `life` with `fight`, then `resend`. A fighter's `progress` while its fight runs (`Fights.playerFighting`) is acknowledged with nothing credited or written, and its close writes no checkpoint: the settlement writes its records. A lock still asking is free play: reports credit, a close writes the checkpoint, and `start` takes each side's latest clock.
- The object has one alarm slot. Only `Authority.rearm` sets or clears it, as the earliest of the hello timeout, `Beacons.nextDue()`, the 15 s admission-queue tick (held only while someone is queued) and the fights' watchdog (`Fights.watchDue()`: each running fight's frame 0 + the 90 s timeout + 1 s, so an evicted object still wakes to settle it); new alarm users extend it instead of calling `setAlarm`.
- Proof reads (M9 T7, ADR 0055): `GET /v1/proof/<creature>` and `GET /v1/fight/<enc>` are checked in `index.ts` (origin as `publicJson`, then 400 `id` for anything but 64 lowercase hex), answered from `caches.default` when it holds the path (a hit never reaches the object), else by the RPCs `Authority.proof` and `Authority.fight`, and their 200, 404 or 413 is cached without CORS headers (`MAX_AGE`: a day for a settled fight, 10 minutes for a dead creature's bundle, else 60 s). The object counts each one in the usage meter (`usage.request`) and answers 503 `busy` past 80% of `requestBudget(env)`. `worker/proof.ts` reads SQLite itself and only reads (every query adds its `rowsWritten` to the ledger's count, so a test sees none): `proofBundle` walks the ancestors breadth-first (nearest first, ties by id, through each birth's parents and each child `promote`'s chain parent) and cuts each at its last tie to a held child (`mate-commit`, parent `promote`, or the death of a chain parent that died first), growing through `Growth` (sizes and record counts kept per added creature, so a bundle is assembled once) and stopping at 64 creatures or before 512 KB or 4,096 records with `more` naming the parents left out; a subject whose own chain passes the caps is `413 too-big` (the card says "too long to check here", the CLI exits 2); it reaches only creatures that the subject's records name. Each event its records hold (a fight whose settlement it holds, a genesis, a mating) brings its witness commitment while kept (found by its request key, `requestKey('witness', '', { event })`) with that round's beacon, and every attestation of it; they count toward the bytes and the list caps (M10 T10). A settlement's transaction also deletes up to 4 resolved witness commitments made 14 days or more before (`Beacons.pruneWitnesses`, on the beacon source's clock, as `created` is: in fixture mode it is not `hub.clock`); attestations stay. `fightProof` serves the settlement and the row's log (the pond seed is the settlement's), null until settled. Keys are read from `keys` directly: a proof read never makes one.
- The Worker has two entries: `index.ts` (production, live drand) and `e2e-entry.ts` (recorded rounds, `node tools/worker.mjs dev --e2e`). Fixture code and E2E hooks (`POST /v1/e2e/pre-reset`, M6c T2; `POST /v1/e2e/restart`, M8 T5; `GET /v1/e2e/encounter/<id>`, M8 T9; `GET /v1/e2e/witness/<event>`, M10 T4; `GET /v1/e2e/directory`, M11 T6; `GET /v1/e2e/metrics`, M13 T1; `GET /v1/e2e/sessions`, `/v1/e2e/audit` and `/v1/e2e/dropped`, M13 T7) live only in the latter; `tools/worker-bundle.test.ts` guards that.
- Hub tests that need beacons swap the live object's `source` field (`worker/test-hub.ts`: `login`, `hatch`, `useFakeBeacons`, `publish(round)` moves a fake clock and runs the alarm), so no test waits for real rounds. A court needs the directory to place both partners, so mating tests report their players first (`placed`, which takes the `near` off the socket and keeps every other message). Tests that need the wall clock (progress, lifespan) mock `Date.now` (`worker/progress.test.ts`).
- A creature's per-connection state (`LifeState`, `worker/life.ts`) lives in the socket attachment and is written to SQLite only as checkpoint records; keep it small (2 KB limit). Its bounds hold per record interval (ADR 0055, as the verifier checks them): the credit since the last record (`boundT`, `boundMs`) is at most the wall time since it plus 2 s, a report's growth is clamped to `reachAt` from that record's biomass (`boundBiomass`) over the active time since it, and a lock-in claim (`clampClaim`) over the wall time since it. Every path that writes a record of the connection's creature passes the life through `recorded(life, t)` (a checkpoint, a death, a mating, a settlement); a new binding (sign-in, genesis, promote, restore) starts from the head. A mating's records take the session's last report, so the client reports just before a court or an accept (`MateDeps.fresh`), or the next bounds would cut the growth it played since. Ticks claimed beyond the wall time since the binding (`startT`) plus 2 s are `clock-too-fast`. A mating also needs the maturity size (`LifeState.matureBiomass`, from `matureBiomassOf` under the object's scales), which `ownRefusal` checks when the view carries it.
- The audit (`worker/audit.ts`, M9 T8): `FLAG_KINDS` is the one catalogue of flag kinds, each documented where it is raised, and each raised through `hub.ledger.audit.raise(kind, { owner, creature, key, t })`, one row per kind and request (`key`: a request hash, an encounter, a player, a commitment or a mate ask) or per kind and creature, however often it repeats. `replay` is an owner-signed request for a head its chain has moved on from (`movedOn` in `ledger.ts`; the refusal stays `conflict`), a genesis ask whose creature already came, or a mate ask whose nonce a commitment used; an accepted request sent again keeps its idempotent answer and no flag. `GET /v1/audit` (`Authority.audit`, metered and 503 `busy` past 80% of the budget as proof reads are (`meterRead` in `proof.ts`), edge-cached 5 min through `edgeCached` in `index.ts`) counts the flags by kind for the UTC day and since `world.reset_at`, with no ids.
- The hub's cost per message (M13 T6, ADR 0067): `worker/hub-cost.test.ts` (a `speedTest`) seats 50, 200 and 500 sessions and sends batches of 200 through the object's own `webSocketMessage` inside it, the hand clock moving 1 s per message (then `clock.advance(0)` runs the timers that fell due, outside the timing), timed on `performance.now()` (the local runtime's clock steps by 1 ms; production's stands still, so only a test can measure this). `npm run report:hub` writes `docs/perf/hub.md` and `hub.json` from its `HUB_COST` line. Each type's cost at 500 may be at most 1.5 times its cost at 50 plus 0.02 ms (`inBudget` in `tools/hub-report.ts`); `spawn` alone may grow with the members (`place()` reads every member).
- The meter (M13 T1, ADR 0067): modules reach SQLite only through `hub.sql`, the handle `meteredSql` (`worker/metered-sql.ts`) wraps so that each statement's rows read and written count into `Authority.rowCount` (a cursor is counted as it is consumed; an unconsumed read isn't counted), which `UsageMeter` reads beside its own raw handle (so its flush isn't counted twice). Never use `ctx.storage.sql` in a module. The meter (`worker/usage.ts`) holds `UsageDay`: messages by type (`bad` for an unparsed one), upgrades, public reads, rows, seated player-time (integrated on each change of `meterSeats` in `sessions.ts`: enter, drop and the queue), the peaks and the waits (a queued attachment's `queuedAt`); its row is written at most once a minute (migration 13 added the columns). `GET /v1/metrics` (`worker/metrics.ts`, `Authority.metrics`) is edge-cached 60 s and, unlike the proofs, still answered past 80% of the day's requests. Plan limits come from `limitsOf(env)` (`worker/plan.ts`, `PLAN`). A `progress`'s `relay` (M13 T4) goes to `usage.relayed` whatever the report credits (`meterRelay` in `lives.ts`), its KB clamped to 4 KB/s per reported link over the wall time since the session's last counted report (`Session.relayAt`, else `openedAt`), at most 60 s.
- Admission (`worker/usage.ts`, `admissionWhy` and `canAdmit` in `worker/sessions.ts`): `admissionWhy` names the guard that holds, `budget` (90% of the day's requests) before `full` (the session cap), and every `queued` carries it as `why` (M13 T4); `MAX_SESSIONS` and `DAILY_REQUEST_BUDGET` are `vars`; a hub test sets them on the live object's `env` (`worker/queue.test.ts`). A queued socket has phase `queued` in its attachment and costs no SQLite writes.
- Witnesses (M10 T4, ADR 0058, migration 10): `worker/witness-pool.ts` decides eligibility from the witness candidates and each candidate's attachment (seated, `avail` on, which an `on` sets at most once per 5 s and an `off` at once; not locked; no duty held; fewer than `DUTIES_PER_HOUR` accepted, as `Session.duties` times; an IP hash, SHA-256 of `world.ip_salt` and `CF-Connecting-IP` set in `Authority.fetch`, that no participant's session shares), the saved play (the owner's `creatures.active_ms`, plus the seated session's credit since) and the strike (`players.struck_until`), both kept in the candidacy (above). `commitWitnesses` writes an event's one witness commitment (`Beacons.commit('witness', '', { event, pool }, { round, key: { event } })`: the round is a function of the commitment's time, never a round already due, and the request key is the event's, so the req index finds it): an encounter's on `witnessRound` right after `enc-start` goes out (`engage.ts`), a genesis's and a mating's on their own round (`lives.ts`, `offspring.ts`), never pooling the participants; an empty pool, or a commitment that throws (a round already due), writes none and flags `authority-only` once per event. `hub.duties` (`worker/duty.ts`, memory only, so a restart ends every duty) draws the order when the alarm resolves the round, offers a running fight's referee at once (`duty` with the fight's start and history, `duty-peer` to each fighter) and an auditor once `offerAudit` hands over the case; an offer goes to the next unused, unreserved position whose player is eligible (one `eligible` pass over the positions left, each candidate's play credited from its own session), and `duty-no`, `OFFER_MS` (5 s) of silence or a close moves it on, at most `MAX_OFFERS` (3) per duty. `duty-ok` from the player offered calls `onReferee` or `onAuditor`; anyone else's is dropped (`strays`). `strike` sets `struck_until` a day ahead, flags its kind once per key and ends a duty held (`duty-end { why: 'struck' }`). The signal relay (`relay` in `sessions.ts`, M10 T6) passes a signal anywhere between a referee witness and its fight's fighters while that duty is offered or taken (`hub.duties.linksOf`), and between sessions the directory places within reach (M11 T6, below); anything else is `no-peer` (M11 T14: there are no ponds). `WITNESS_PLAY_MS` and `WITNESS_IP_CHECK=off` are read in fixture mode only, and `POND_MAX` nowhere (`tools/worker-bundle.test.ts`); hub tests use `worker/witness-test-kit.ts`.
- A witness referee (M10 T5, ADR 0058, `worker/witness-fight.ts`; `fights.ts` keeps its referee loop and hands a running `Fight.witness` phase to `witnessTick`): on `duty-ok`, `handOver` picks `h = referee.next + 3`, appends the span to `Fight.spans` (saved in the row's `referees`, `FightStore.referees`, one row), sends `enc-referee` to the fighters and W, then W the frames finalized since its offer and each one before `h` as it comes. The authority finalizes frames before `h`; a fighter's input from `h` is dropped as `moved` (`Fights.witnessed`, with `batches`, `repeats`, `strays` and `disputes`). A `batch` (only from the phase's W) must continue the log (`f` = `enc.frame`; one wholly before it is a repeat, ignored), have each frame's width and carry `inputSigned` under each slot's key (tabled once at the handover) for every input, codes at most `0xFFFFFFFE`, and reach at most `BATCH_LEAD_MAX` (10) frames past the frame due on the hub's clock; it is stepped through `stepAll`, echoed and written as one row (`flush`). The phase keeps the lock's one timer (`wakeAt`: the frames before `h`, the batch watchdog at `start(next + 10) + BATCH_GRACE_MS`, a planned gap's wait at `start(h') + BATCH_GRACE_MS`, the away wait). A failure (`witness-silent`: the watchdog or W's close through `witnessLeft` in `drop`; `witness-forged`; `witness-equivocated`: a fighter's `dispute` with W's valid signature on a frame other than the one W batched, as `Fight.batched` records; for `DISPUTE_AFTER_MS` (30 s) after the fight's lock is released its players, batches and batched frames stay in `Fights.settledFight`, and a later dispute only strikes W) announces `h' = max(takeBackFrame(enc.frame, due), h + 1)`: a span to the authority, a `Referee` restored at `h'` (the one before `h` kept as `pre` for its frames), `enc-referee { by: 'authority' }` to the fighters and W; then strikes W (flag once per event, `duty-end struck`) and fills the gap with the fallback at once. A planned take-back (`takeBack`: a join in `admit` before it seats, everyone away inside `witnessTick`, W's own lock-in through `witnessLocked` in `engage.ts`'s `start`, so a lock refused at its answer leaves W's fight as it was) announces `due + 3` and waits for W's final batch, else the fallback; nobody is struck. Once the log reaches `h'` the phase closes: a planned W hears `duty-end taken-back`, and but for everyone away the next position is offered (`reoffer`). `settle` names `refereeingOf` (the spans that refereed a frame, and the witness commitment's id) in the version 2 settlement and ends the duty `done` (`witnessDone`). A rebuilt fight (`recover.ts`) keeps the saved spans that refereed a logged frame and hands the rest to the authority from the log's end. Recovery finds a held fight by its encounter too (`Fights.ofEncounter`): a lock-in's lock has its own id. Hub tests drive a `ScriptedWitness` (`witness-test-kit.ts`). `Authority.received` counts incoming messages by type (the cost check).
- Audits (M10 T8, ADR 0058, `worker/attest.ts`): `auditFight` (in `settle`, with the log and the signed settlement), `auditMating` (in `deliverBirth`, both births in slot order, the mate-commits and the parents' genome texts `a` first) and `auditGenesis` (in `deliverGenesis`) hand the case to `hub.duties.offerAudit`, which offers it now or once the round resolves (a fight's settled players never audit it). `duty-ok` starts `ATTEST_MS` (60 s, `awaitAttest`); silence offers the next position (`silent`, nobody struck). An `attest` from a player holding no taken auditor duty is dropped (`strays`); from the auditor it must parse, be `attestationSigned`, and name the duty's event, commitment id, the auditor's position (its player there in the order) and the authority's own subject (`auditSubject` in `src/net/audit.ts`). Then it is stored, one `attestations` row: one that agrees ends the duty `done`; one that disagrees is overruled, its auditor struck (`audit-overruled`) and the next position offered (`reoffer(event, 'auditor')`). One that fails is dropped, its sender struck (`attest-forged`) and the next offered. When the auditor role has nobody left to offer (`Duties.spent` calls `onAuditEnd`), an event with no witness span and no agreeing attestation is flagged `authority-only` once. Hub tests sign each attestation from the duty's own case (`auditVerdict`, `worker/attest.test.ts`); a player hatched with witnesses online has its genesis audited, so tests that count offers hatch their players first.
- `LIFESPAN_SCALE` and `MATING_SCALE` (fixture mode only, with `DRAND_SOURCE=fixture`) shorten the lifespan, and maturity, cooldown, the repeat window and the restore minimum; they are read only through `scalesOf(env)` (`worker/mating.ts`), which the shared rulebook's gates (`src/ledger/gates.ts`) take, and `tools/worker-bundle.test.ts` guards that. Hub tests set them on the live object's `env` (`worker/mating.test.ts`). A courtship's invitation lives in the courting socket's attachment (`court`), never in SQLite; `worker/mating.ts` must export nothing that edits a stored round.
- The directory (M11 T6, ADR 0062): `worker/directory.ts` is the pure quadtree (no Hub: the headless harness and `worker/directory.test.ts` run it in Node), `worker/where.ts` its handlers on `hub.directory`, in memory only. The world square is the root; a leaf splits in four above `LEAF_MAX` (16; `LEAF_MAX` 1–16 in fixture mode, `leafMaxOf`) unless it is 1,024 wu wide, and four sibling leaves merge below `LEAF_MIN` (6, scaled by `leafMax / 16` so a merged leaf never splits at once). A `where` writes no row: it is checked (a centre outside the world, a first report under a binding that its anchor doesn't hold (`anchorHolds` in `spawn.ts`), or a jump past `WHERE_SPEED_WU` × the seconds since the last plus `WHERE_JUMP_WU`, is dropped and counted in `Authority.dropped`; a jump is taken after a new life binding, `creature:startT`, and always in fixture mode, which takes both), kept in the session's attachment (`Session.where`, so the constructor's `rebuildDirectory` restores the tree on a wake) and answered with `near` (the 48 nearest linkable members within Q = max(8,192, 4 × aoi) anywhere in the world, the 64 nearest two tiers smaller within the AoI as `swarm`, positions in 1/8 wu, the farthest dropped to fit 8 KB). Members a split or merge re-leafed hear `leaf`. `gone` and a closed socket (`drop`) take the member out. The directory also decides the relay's reach (`relayReach`: within max(Q_a, Q_b) + 4,096 wu, and a relayed signal carries the sender's position as `at` and its link class `cls` when it named one; `hub.relays` counts signals by pair), courts (`courtTooFar`: `mate-check` answers and `court` is refused `not-near` past 12,288 wu, or unless it places both) and carrion (`carrionNoticed`: every member within 10,000 wu of the kill, besides the fight's own players, each reached through the seat index). Each `near` peer carries its instance `n` (M12 T5, below). The welcome holds no `members` and no spawn hint, there is no `member` message, and an engage between any two seated sessions is refused only by its own checks (M11 T14). `GET /v1/e2e/directory` (E2E entry only) shows it.
- Spawning (M12 T4, ADR 0064, `worker/spawn.ts`): a seated session's `spawn` is answered with `place()` (`worker/placement.ts`) over the directory's other members, the hub's recent spawns (`hub.spawns`: the last 256 of the minute, in memory), the world row's centre and the world's seed, size and pond tick, drawn from `crypto.getRandomValues`; the spawner is the life's radius and adult radius (`spawnerOf`), else the message's `r` and `aoi` (an unrecorded cell). A creature locked in a fight is refused `spawn`; a repeat under the same binding gets the same answer (`Session.spawned`, which `gone` clears). A genesis and a restore set `Session.protectBind`, and their answer is `protect: true` with `protectedUntil` from the answer; a resume and a practice cell are unprotected, and a promote stays protected from the promote. A resume (M12 T10, `leftPlace`) whose creature left the water under `BACK_WITHIN_MS` (10 minutes, on `hub.clock`) ago comes `back` there: `Session.left` on the same socket (`gone` keeps it), else the player row's `left_x`, `left_y`, `left_at` and `left_creature` (migration 12), which a close writes from the last report (or `Session.left`) of the creature it plays, one row in the checkpoint's transaction (`saveLeft` in `saveOnClose`), and a settlement writes for a fighter away at its end from its final position (`leftAt`). The answer puts the member in the directory at once (`whereIn`, as a report would) and sets `Session.anchor` (`{ x, y, t, bind }`); a promote anchors at the parent's last report (`Session.where`, or `Session.left`, which `gone` keeps), a fighter seated back into its running fight at its place in the authority's encounter (`fightAnchor`), and a fighter at a fight's end at its final position in the authority's encounter (`settleLife` and `backToLedger` in `settle.ts`, M12 T10; a recovery that gives up, at the last report). `worker/transitions.test.ts` (a `heavyTest`) plays 30 seeded runs of random steps through the hub and checks after each that every creature has one place and one state. `anchorHolds` checks only the first report under a binding since its anchor: past 300 wu/s since the anchor plus 2,000 wu it is dropped and flags `teleport` once per creature (none for a practice cell), and with no anchor for the binding it is dropped. Writes no row but that flag. Hub tests use `spawned(p)` (`fight-test-kit.ts`) or `anchorAt` (`test-hub.ts`).
- Riding the current (M12 T7, ADR 0064, `worker/ride.ts`): `Session.aloneSince` is set by a `near` with no peers (kept while they stay none) and cleared by one with any, by `gone`, and by a granted ride. A `ride` is refused (`ride-no`), in order: `locked` (a fight or a lock), `busy` (a live court of its own or naming it), `soon` (within `RIDE_AFTER_FIGHT_MS`, 120 s, of its last fight's end, `Fights.fightEnded(id, RIDE_AFTER_FIGHT_MS)`, which keeps each player's last end that long; or alone under `rideAloneMsOf(env)`: 120 s, `RIDE_ALONE_MS` of at least 1,000 in fixture mode only), `company` (the directory places a member it can link with and shares water with within its Q now), `soon` again (never seen alone, or not in the directory), `none` (`place()` found no group, or fell back to the centre). Otherwise it answers `spawn { why: 'ride', protect: true }` at `place()` over the others and the recent spawns (the ride is remembered as one), anchors the binding there, sets `protectedUntil` from the answer, and puts the member in the directory at its arrival at once (`whereIn`). Writes no row. Hub tests in `worker/ride.test.ts`.
- Crowd instances (M12 T3, ADR 0064): `worker/crowds.ts` is pure (no Hub; its tests run in Node beside the directory's) and run by `hub.crowds` (T5), the harness and the wave. `Crowds.report(member, crowd, now, ctx)` takes every `where` with its crowd list (non-null means crowded; the sender's own id in it pairs no one), `settle(now, ctx)` runs what `due()` says, `remove` a member that left the water, `restore` the (crowd id, instance) pairs of the attachments after a wake (`crowdOf` gives the crowd id), `view()` the crowds; each returns the `Moved` members to tell. `CrowdContext` gives `locked`, `partners` and the directory's `around`. Forming: a crowded report from the open water with no crowd member within its P1 reach (8 × the larger radius + 600 wu, and `linkTiers`) asks for a crowd `SPLIT_WAIT_MS` (3 s) later, of the reporter and the unlocked open-water members within that reach, if two or more, in max(2, ⌈n ÷ `INSTANCE_MAX`⌉) instances. Units (a member with its partners, and the pairs of crowd lists under `CROWD_LIST_TTL_MS`, 10 s, a later list replacing its sender's earlier one) go whole into the least-full instance with room, the largest first, and a new instance opens when none has room; a unit past `INSTANCE_MAX` takes an empty one to itself. Joining (an open-water report within P1 reach of a crowd member) takes its partner's instance, else the one holding most of its list pairs (its own list and the members' lists naming it) when that has room, else the least-full; leaving is past 2 × (8 × the larger radius + 900 wu) of every other member, checked on its report and when a member goes. More room: a crowded report from inside re-bins 3 s later, at most once per `RESPLIT_GAP_MS` (10 s) per crowd: units stay while their instance holds at most `INSTANCE_MAX` (a unit with a locked member always), and the overflow goes to a new instance, else the least-full with room; a new instance nobody needs is not taken. A crowd merges after `QUIET_MS` (30 s) with at most `INSTANCE_MAX` members, no list from them and no locked member, judged at each `settle` (a lock seen there restarts the wait); an empty crowd ends at once. Locked members never change instance: forming leaves them in the open water, and joins, leaves, re-bins and merges pass over them. Instance numbers go round 1 to 65,535, never one a live crowd holds. On the hub (M12 T5, `where.ts`): every `where` reports to `hub.crowds` after the directory (its `crowd` with the ids that aren't seated dropped), with the context `crowdContext` builds (`locked` and the fight's other fighters from `hub.fights`, live court partners both ways from the courts' index, `around` from the directory); one one-shot timer on `hub.clock` (`armCrowds`, `hub.crowdTimer`) runs `settle` at `due()`, no loop and no alarm; each member whose instance changed hears `instance { n }` and its attachment keeps `crowd: { id, n }` (absent in the open water), from which the constructor's `rebuildCrowds` restores the crowds on a wake (E2E `restart` too). `gone` and a close take the member out (an open socket hears `instance { n: 0 }`), except a locked fighter in an instance: it stays in `hub.crowdsKept` until its fight ends (`releaseKept`, at the next report or settle), and `enter` gives it back its instance (`reseatCrowd`; after a wake, a fellow fighter's crowd and instance). Wherever the hub decides, only sessions that share water (`sharesWater`) meet: `near` and its swarm (`Directory.near`'s `instanceOf`), the relay (`no-peer`, a duty pair excepted), courts (`courtTooFar` answers `not-near`), engages and joins (`engage:instance`: the target, and every fighter still in for a join) and carrion notices (`carrionNoticed` by the victim's instance, besides the fight's players). `INSTANCE_MAX` (1–16) and `QUIET_MS` (at least 500) are read in fixture mode only (`instanceMaxOf`, `quietMsOf`). Hub tests swap `hub.crowds` for fresh `Crowds` (`worker/instances.test.ts`).
- Seat tickets (M11 T7, ADR 0062, `worker/seat.ts`): `enter` sends the welcome's `ticket` (dated on `hub.clock`, the world's seed as its `world`) and keeps its time in `Session.seatAt`; a `ping` from a seated session at least `SEAT_RENEW_MS` (10 minutes) after it is answered with `pong` and then a fresh `seat`. A queued session gets none. Tickets are signed through `Ledger.countersign` and write no row.
