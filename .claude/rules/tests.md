# Tests

- Offline and deterministic:
  - Relays, STUN, TURN, drand and the Cloudflare API are faked or replayed from recorded fixtures (`tests/fixtures/`).
  - The authority runs locally (workerd, `wrangler dev`), and E2E sets the authority URL at runtime (localhost only), never the production one.
  - Every random input is seeded.
- Unit tests sit next to the code (`src/**/*.test.ts`). E2E runs against `dist/` (`tests/e2e/*.spec.ts`).
- Tag scenarios longer than about 20 s with `@slow`. They run only in `test:e2e:full` (the release gate). The PR E2E suite should stay under about 3 minutes in CI.
- Visual checks assert properties of decoded screenshots (non-blank, contrast, an element present, budgets from `renderer.info`), never pixel-exact baselines: software rendering changes between browser versions.
- Every E2E context starts on the low preset (`storageState` in `playwright.config.ts`): the post chain makes software rendering several times slower. Specs that judge the picture or the presets clear it with `test.use({ storageState: { cookies: [], origins: [] } })` and pass `?quality=`.
- Use the `window.__bs` hook (`?debug=1` for mutations) instead of sleeping or scraping the DOM for game state.
- `window.__bs` (`src/game/debug.ts`): `ready`, `state()` (screen, `zone` and `depth` under the player (null on the title; M6 T16), quality (`setting`, `detected` the preset auto resolves to, `bench` `pending|running|measured|stored|skipped`: automation is `skipped`, a stored result for this GPU `stored`), tick, player, death, life (the recorded life: `status` is the client state machine `idle|requesting|awaiting|verifying|playing|dead|practice`, plus `creature`, `genome`, `activeMs`, `lifespanMs`, `awaitingBeacon`, `lastAckN`, `ackedBiomass` (the biomass in the report the hub last took), `genesisIn`, `practice`, `stage`, `remainingMs`, `limitMs`), mate (`state`, `text` the line on screen, `invite`, `visited` states, `ready`), offspring (`kind`, `creature`, `species`, `rarity`, `generation`, `genomeHash`, `cardShown`, `eggShown`, `options` the ids of the title and death choices), remotes (each with `radius`, `genomeHash` and `species`, null while the tinted cell stands in), pond, social, net (`dropped` counts genome events ignored); `player` includes `speed`, `elder`, `genomeHash`, `species`, `rarity`, `tier` and the sim's `stats`), `events()` (counts since hatching), `replay(log)` (hash of an input log), `render.info()` (`remoteCells` fallback cells, `remoteBodies` genome bodies; `preset`, `pixelRatio`, `particles`; the post chain's `passes`, `targets`, `targetBytes`, `renderScale` and `dof` (`none|half|full`); the player body's `lod` (`high|medium|low`, null without a body) and mesh `vertices` (M6 T10); `caustic` (the caustics' strength at the camera) and `rays` (the god rays' strength drawn, always 0 on low; M6 T17); `calls` and `triangles` count the whole frame, every post pass included), `render.specks(layer)` (`far|mid|near`: each on-screen speck's `index`, CSS-pixel `x`, `y`, `size`, depth `z`, CoC `blur` and `bright` (one of high's bright specks, M6 T17), as last drawn). With `?debug=1` also `debug.{setEnergy, setBiomass, teleport, setZone, nearestFood(kind?), steerTo, spawnPlume, setRemotes, joinPond, deliver, hasFood, timeScale, resetWater, setBench}`; `setZone(zone)` teleports the player to the nearest point well inside that zone (clear of its edge bands, its surround in the zone too) and returns it (M6 T16); freeze the world first (`timeScale(0)`) where UV or pressure would hurt; `setBench(ms)` replaces every measured frame time with `ms` and re-runs the auto-detect benchmark at once (8 high, 15 medium, 30 low), and adaptive resolution follows it, which is otherwise pinned at 1 under automation (low folds `renderScale` into `pixelRatio`); `steerTo` returns a promise; `timeScale(0)` also holds the shaders' animation clock, so specks stand still for screenshots; `resetWater()` zeroes the marine snow's flow and, once frozen, the shaders' clock (M6 T17), so two frozen pages hold the same specks. `?dof=0` draws every preset without its depth of field and `?light=0` without caustics or god rays (test switches). A scripted remote (`setRemotes`) may carry a `genome` (any text, delivered through the real parser and builder; `withholdGenome` sends only the ref). The game hatches a random genesis body unless `?genome=<base64url>` or `?genome=starter` pins it; `openGame` in `tests/e2e/helpers.ts` adds `genome=starter` unless the query pins one. Tests click Hatch first: the page opens on the title screen, and `state().player` is `null` there.
- `window.__lab` (`src/lab/hook.ts`, always present on `lab.html`): `ready`, `state()` (seed, mode, creatures (each with its `silhouette` class, M6 T8), hovered, selected, parents, offspring), `select(i, { second })` (0-23 the grid, 24-31 the offspring strip), `setMode(mode)`, `renderInfo()`; with `?debug=1` also `debug.{showGenomes(base64url[]), pause(), advance(seconds)}` (replace the grid with those genomes, freeze and step the gait clock for screenshots; a paused Lab also holds the film grain, so a redraw of the same time is pixel-identical, M6 T11). Lab specs measure decoded screenshots of `[data-testid="lab-canvas"]` cell by cell (`cellRect` and `stageCoreRadius` from `src/lab/grid.ts`; helpers in `tests/e2e/lab-helpers.ts`); the page must make no request outside its own origin.
- `window.__gallery` (`src/lab/gallery-page.ts`, on `lab.html?gallery=1`, M6 T5): `ready` (true once the sheet is drawn; it never redraws), `state()` (`width`, `height`, `cols`, `rows`, `radius`, `specimens` with `file`, `comment`, `hash`, `species`, `rarity`, `vertices`, `valid`), `renderInfo()`. The sheet is fixed at 1600×1000 CSS pixels, pixel ratio 1, high preset, still grain and a fixed gait time; specimens are `tests/fixtures/gallery/*.hex` (a `# comment` line, then hex) in file-name order, and the first 20 are pinned by hash in `src/lab/gallery.test.ts`. `captureGallery` in `tools/gallery-capture.mjs` is shared by `npm run gallery` and `m6-gallery.spec.ts` (in the `post` project).
- `state().social` holds `chat` (the last 50 lines), `muted` (player ids), `emotes`, `pings` and `dropped`; E2E chats through the real UI (Enter, type, Enter; click a roster name to mute), so there are no chat helpers under `?debug=1`.
- `state().indicators` (M6 T19): the edge indicators as drawn (`kind` `player|ping`, `id`, `name`, `ping`, `angle` the world bearing from the player in degrees, `lengths`, `size` `smaller|comparable|bigger`, `ready`, CSS-pixel `x`, `y`); `state().map` (`open`, `players`, `pings`). The DOM has `edge-indicator` (`data-kind`, `data-id`, `data-size`, `data-ready`), `pond-map`, `map-frame` and `map-dot` (`data-id`, `data-self`, `data-ready`; measure its `svg`). A scripted remote may carry `ready`. `m6-find` has its own hub on 8797 (`M6_FIND_HUB`).
- Hub E2E: Playwright starts `wrangler dev` on port 8787; open the game with `?hub=http://localhost:8787`. Tests in a file that uses the hub run serially (`test.describe.configure({ mode: 'serial' })`), because the hub fills the fullest pond first. Files run in parallel, so each hub file has its own `wrangler dev` (`playwright.config.ts`: `m2-online` 8787, `m2-social` 8788, `m2-pond` 8789); a new hub file adds a port (`m4-*` share 8790, except `m4-oldage` on 8791 with `LIFESPAN_SCALE=0.01`; `m5-*` on 8793 (`m5-inspect` alone on 8794, `M5_INSPECT_HUB`; `m5-promote` on 8795, `M5_PROMOTE_HUB`; each M5 spec file gets its own hub, since files run in parallel and share a pond otherwise) with `LIFESPAN_SCALE=0.05` and `MATING_SCALE=0.01` (`M5_HUB`); `m4-lifecycle` (`@slow`) on 8792 with `MAX_SESSIONS=2`, `M4_TWO_SEAT_HUB` in `helpers.ts`; every hub starts with `--e2e` so a hatch without a pinned body finds recorded drand rounds). `window.__bs.life.recompute()` returns the round, commit id and DNA hash recomputed from the last genesis, to compare with `tests/fixtures/drand/`; `?genome=` pins a practice cell that never touches the ledger, so a test of the ledger opens the game without it (`openRecorded` in `tests/e2e/helpers.ts`).
- Golden files- M5 hubs (each spec file its own, `playwright.config.ts`): `m5-court` 8793, `m5-inspect` 8794, `m5-promote` 8795 and `m5-lifecycle` (`@slow`, 8796, `M5_LIFECYCLE_HUB`) with `LIFESPAN_SCALE=0.02` (lives of 1 to 2 min), because the authority credits at most wall time: old age cannot be fast-forwarded past real time. `ripe(page)` runs the sim at 30x until maturity is credited.
- Golden files (replays, math, genome vectors) change only together with a `RULES_VERSION` bump.
- Never skip, loosen or delete a test to get green; fix the cause.
