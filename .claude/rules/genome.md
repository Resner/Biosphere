# Genome and development (`src/genome`)

ADR 0006 is the contract. This code is shared and deterministic, so `.claude/rules/sim.md` applies too.

- Decoding and development are total functions: any byte string decodes, and any genome develops into a valid body. Clamp and repair; never throw and never reject.
- Hard caps from ADR 0006 (segments, appendages, joints, collision circles, bounds) are enforced in development, not in rendering. Parts are capped by count only: mesh vertex budgets belong to `src/render/creature-mesh.ts`, which lowers detail and never drops a part (ADR 0025).
- Property tests over at least 10,000 random genomes plus 10,000 mutated or recombined descendants run on every change: no throw, caps hold, there is always a propulsion source and a mouth.
- Function follows form: abilities come from geometry and material parameters through formulas. Never hard-code a stat on a named part ("spike = +10 attack").
- Every benefit has a cost (mass, metabolism, drag, cooldown). Archetype tests must show that no genome is best at everything.
- One live rules version, no frozen versions before v1.0 (ADR 0040): a change to development, expression, inheritance or genesis bumps `RULES_VERSION` and regenerates the goldens, and the old code is deleted, not kept. A version change that changes what records mean resets the world (its own task: a worker migration, a protocol bump, the notice); `checkGenesis`, `checkBirth` and `checkStored` answer `rules-retired` below `FIRST_LIVE_RULES` (`src/ledger/record.ts`). From v1.0 (or M9's verifier, if earlier) versions are frozen again. `deriveSeed`/`offspringSeed` in `inherit.ts` stay as they are within a version.
- `genesis.ts` holds the whole genesis draw (the base cell, then the larval form and bristles from their own stream); `rarity.ts` prices features from its tables. Bodies follow `develop.ts` and `stats.ts`, and `statsAt` passes the top speed through the band of ADR 0036.
- Karyotype v2 is the only karyotype: the 164 bytes of base loci (laid out as v1 had them), then the shape loci and the slot extensions, each reading 0 as off. Any byte string decodes as v2, zero-padded or truncated (328 bytes too). Body proportions follow the v2 layout for every genome (ADR 0028). A slimmed long chain is laterally compressed (`form.slim`, ADR 0031): stats read its girth, so look tuning of the outline never moves the balance. A bilateral v2 chain of 3+ segments is one body widest at the trunk (ADR 0037): the head is a share of the trunk's width, so its profile does move the stats; re-run the balance checks after changing it. A curled chain fits the bounds along its curve (ADR 0038): a C or S grows longer, a coil (gated by ADR 0041: segment genes for 5+ segments and at most 2 leg pairs, else the C-curl) is a chambered spiral of `caps.segments` segments, and no two segments that are not neighbours overlap (`bodyViolations`), so curl changes move the stats too. Parts keep off the body and are drawn thin on a slim segment (ADR 0039): `width` is drawn, `girth` is the gene's width that stats, bristles and bulbs read, so thinning moves no balance; `keepOff` and `uncover` do move parts, so re-run the balance checks after changing them. Parts are read by region (`organism.ts`, ADR 0041): head, trunk and rear limits and a budget of 14 visible instances; the rest becomes fringe (`fringe: true`), which stats count like any part, so re-run the balance checks after changing a limit. Property tests of plans extend the shared 10,000-genome cache in `develop-curl.test.ts` rather than adding another loop. `tests/body-outline.ts` holds the outline, class-shape and curl measures (`trunkCheck`, `classCheck`, `spineTurn`, `sArcs`, and M6b T7's `insideShare` and `trunkLegs`).
- Offspring randomness comes only from the committed seed (beacon, commit id, slot) through named streams. No other entropy.
