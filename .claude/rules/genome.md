# Genome and development (`src/genome`)

ADR 0006 is the contract. This code is shared and deterministic, so `.claude/rules/sim.md` applies too.

- Decoding and development are total functions: any byte string decodes, and any genome develops into a valid body. Clamp and repair; never throw and never reject.
- Hard caps from ADR 0006 (segments, appendages, joints, collision circles, bounds) are enforced in development, not in rendering. Under rules 6 parts are capped by count only: mesh vertex budgets belong to `src/render/creature-mesh.ts`, which lowers detail and never drops a part (ADR 0025; frozen `develop-v5.ts` keeps the v5 vertex rule).
- Property tests over at least 10,000 random genomes plus 10,000 mutated or recombined descendants run on every change: no throw, caps hold, there is always a propulsion source and a mouth.
- Function follows form: abilities come from geometry and material parameters through formulas. Never hard-code a stat on a named part ("spike = +10 attack").
- Every benefit has a cost (mass, metabolism, drag, cooldown). Archetype tests must show that no genome is best at everything.
- Development, expression and inheritance are frozen per `RULES_VERSION`, with golden vectors. A new behaviour is a new version; the old code stays for verifying history.
- Frozen code (never edit; `checkGenesis`, `checkBirth` and `offspringPair` pick it by `record.rules`): `karyotype-v1.ts` (the 328-byte table), `genesis-v5.ts` and `inherit-v5.ts` (rules ≤ 5, with the v5 genetics numbers inlined), `develop-v5.ts` and `stats-v5.ts` (the v1 body under rules ≤ 5, numbers inlined; M6 T7), `deriveSeed`/`offspringSeed` in `inherit.ts` (every version), and the goldens `genome-hash-v1.json`, `genesis-v5.json`, `inherit-v5.json`, `offspring-v5.json`, `develop-v5.json` (tests read them, never write them). Development v2 must keep developing v1 genomes to the v5 plan and stats (`develop-v5.test.ts`).
- `genesis-v6.ts` (the v6 larval forms, its `GENESIS_FORMS` table and golden `genesis-v6.json`) is frozen with rules 6 (M6 T29): `genesisFor` picks the v5, v6 or current code by `record.rules`, and `rarity.ts` reads the v6 table. `genesis.ts` is the working copy for the next rules version; edit it only together with a `RULES_VERSION` bump. Rules 7 (ADR 0035) freezes no development or stats code: bodies follow the current `develop.ts` and `stats.ts` until M7; inheritance, mutation and expression are unchanged since rules 6, so `inherit-v6.json` and `offspring-v6.json` (tests read them, never write them) keep rules 6 births verifying, and `statsAt` passes the top speed through the band of ADR 0036.
- Karyotype v2 appends to v1: a genome keeps its own length (328 bytes is v1, anything else v2), and every new locus reads 0 as the v1 behaviour. This is the v1 equivalence rule: `upgrade` of a v1 genome expresses, develops and scores exactly as the v1 genome did (`develop-v5.test.ts`), so a new locus never changes an old body unless its byte is set. Body proportions (the chain layout and how parts fit the bounds) follow `traits.karyotype` instead (ADR 0028): a v1 genome keeps the v5 layout, every v2 genome gets the v2 one. A slimmed long chain is laterally compressed (`form.slim`, ADR 0031): stats read its girth, so look tuning of the outline never moves the balance. A bilateral v2 chain of 3+ segments is one body widest at the trunk (ADR 0037): the head is a share of the trunk's width, so its profile does move the stats; re-run the balance checks after changing it. A curled chain fits the bounds along its curve (ADR 0038): a C or S grows longer, a coil of 3+ segments is a chambered spiral of `caps.segments` segments, and no two segments that are not neighbours overlap (`bodyViolations`), so curl changes move the stats too. Parts keep off the body and are drawn thin on a slim segment (ADR 0039): `width` is drawn, `girth` is the gene's width that stats, bristles and bulbs read, so thinning moves no balance; `keepOff` and `uncover` do move parts, so re-run the balance checks after changing them. `tests/body-outline.ts` holds the outline, class-shape and curl measures (`trunkCheck`, `classCheck`, `spineTurn`, `sArcs`, and M6b T7's `insideShare` and `trunkLegs`).
- Offspring randomness comes only from the committed seed (beacon, commit id, slot) through named streams. No other entropy.
